# Incident catalog

The catalog contains 25 deterministic, labelled scenarios across five categories:

- resource: CPU, memory, disk, throttling, and process crash
- network: latency, loss, DNS, timeout, and partition
- datastore: connection pools, slow queries, Redis, Kafka lag, and deadlock
- deployment: bad image, invalid environment, secret expiry, API contract, and rollback regression
- traffic: spike, retry storm, rate limit, dependency failure, and multi-service cascade

Each entry has a unique ID, root cause, seed, target service, namespace, affected-service
ground truth, parameters, remediation, and cleanup action. All scenarios are designed for
the aegis-lab namespace and require no manual UI changes.

Validate the catalog with:

~~~bash
python scripts/validate-scenario-catalog.py
~~~

The validator checks count, category coverage, unique IDs/root causes/seeds, required metadata,
and the no-UI constraint. Runtime execution must run each scenario twice, compare the generated
ground truth and parameters, and record duration, blast radius, remediation, and cleanup result.
This repository does not claim those runtime results until they are generated by the fault engine.
